# PDF design

Follow `.claude/rules/pdf-and-printing.md`, `AGENT_BUILD_SPEC.md` §15 and §14, and
`docs/architecture/pdf-and-printing.md`. PDF design work is not authorization to change document
content, layout or templates: those need explicit product-owner approval. Manager Passdown documents
are deferred — never add a Manager template or placeholder.

## 1. Current pipeline (preserve it)

- One QuestPDF generation path in `src/Carowinds.Passdown.Documents/Associate`
  (`AssociatePassdownDocumentModelBuilder` → `AssociatePassdownPdfGenerator`) serves preview,
  print, save and finalization. Never add a second generator or a preview-only rendering path.
- Templates are `ClassicAssociatePassdownTemplateRenderer` (default), `Compact…` and `Modern…`
  behind `IAssociatePassdownTemplateRenderer`, with shared `PdfPrimitives`, `PdfFormatting` and
  product layouts. Daily Feature math renders through `DailyFeatureMath`.
- Documents has no database, network or UI access; it depends only on Application and Domain.
- PDFium (Infrastructure) rasterizes generated bytes for the live preview and supports native
  Windows printing behind platform abstractions.
- `PassdownPdfPreviewViewModel` captures workspace state, schedules background generation with an
  immediate leading refresh and a trailing quiet window, serializes scheduled generations and
  rejects stale results. Do not add another debounce. Engine warm-up and direct bitmap rendering
  stay.

## 2. Output contracts

- Output always reflects the latest edit for the selected date; it can never use a previous date.
  Preview never mutates persisted drafts.
- Finalized snapshots and stored PDFs are immutable and are never regenerated from current prices.
- US Letter, readable in black and white; typical Passdowns fit one page where practical, with the
  established multi-page behavior when content requires it. Never shrink text below readability to
  force one page.
- Only real application data; no prototype or sample content.

## 3. Design guidance (within approved templates)

- Operational values are more prominent than labels and status text; align label/value rows.
- Group related information; avoid decorative boxes, heavy fills and color-only meaning.
- Keep consistent spacing, page headers and typography via the shared primitives instead of
  per-template literals.
- Embedded font changes require PDF equality checks (the embedded Lato set was reduced deliberately).

## 4. Validation

- `tests/Carowinds.Passdown.Documents.Tests` (PdfPig inspection; page count, overflow, content).
  Render-twice comparisons must strip generation timestamps (`PdfInspector.WithoutGenerationTimestamps`).
- Before comparing fonts or first-PDF timing, delete loose `bin/**/LatoFont/*.ttf`; the shipped
  package does not contain them.
- Preview/printing UI: `Phase33PreviewWindowTests` (run alone) and related UI tests; see the
  `build-and-test` skill.
- Inspect real raster output (PDFium or the visual-fixtures harness) for visual changes; actual
  Windows printing must be validated on Windows separately and reported as such.
- Close with the `phase-review` skill.
