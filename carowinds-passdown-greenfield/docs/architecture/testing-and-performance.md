# Testing and performance

Current-state guide — see [review baseline](../architecture.md).

Five production test projects cover Domain, Application, Infrastructure, Documents and UI. The deterministic suite runs `-c Release --filter "Category!=LiveSmoke"` per project, with Ui.Tests split into a mixed partition plus six real-window classes run alone (`OperationsCalendarViewTests`, `Phase15ERealWindowLayoutTests`, `RealWindowStartupTimingTests`, `SpellCheckNavigationLifecycleTests`, `Phase21DMathEditorWindowTests`, `Phase33PreviewWindowTests`); commands are in the `build-and-test` skill. LiveSmoke is opt-in (Phase 37B added `NwsWeatherProviderLiveSmokeTests`: five read-only NWS requests). Weather tests use the committed `fixtures/weather/nws/` files or synthetic snapshots (`Ui.Tests/TestSupport/WeatherUiFixtures`, `FakeWeatherMonitor`) and make no network call; Phase 37C's real-window Weather card tests are a partial of `Phase15ERealWindowLayoutTests`. `tools/visual-fixtures` has `Dashboard37C-*` scenarios and `tools/perf-benchmarks` opt-in `weather` and (Phase 37F) `pdf-weather` benchmarks; `pdf-weather … <outDir>` also writes PDFium renders (colour and grayscale) of the PDF Weather Outlook scenarios and links the Documents test fixtures. Phase 37F PDF layout tests (`Documents.Tests/Associate/Weather`) compare every glyph's baseline with and without weather for all templates. Phase 37D adds Calendar Weather presentation and view-model tests (synthetic snapshots; request-count and subscription checks), real-window partials of `OperationsCalendarViewTests` (Calendar group) and `Phase15ERealWindowLayoutTests` (Settings checkbox), `Calendar37D-*`/`Settings37D-WeatherOutlook` visual-fixture scenarios and an opt-in `calendar-weather` benchmark. The [RC.14 readiness record](../releases/rc14-release-readiness.md) reports 5,893 passing deterministic tests and a 0-warning Release build; not rerun in the documentation review. No CI workflow exists in the repository; validation is run locally and recorded in phase/release records.

Repository guards (`tests/Carowinds.Passdown.Infrastructure.Tests/RepositoryGuards`, 31 tests, part of the normal Infrastructure partition; 21 added after RC.14, 10 in Phase 36B) check mechanically testable repository facts: the `src/` project graph equals the approved dependency table with no cycles and no Domain packages; migrations are numbered contiguously by their own `Version` and every one is registered in the Desktop composition root; the SQLite schema, latest migration and sync/draft/snapshot versions stated in [architecture.md](../architecture.md) and the persistence guide equal source; relative links and back-ticked paths in current documents, rules and skills resolve; archived documents still match their Git blobs; phase records newer than the rule carry both maintenance status lines from the [phase record template](../templates/phase-record-template.md); and (Phase 36B) real `Window`s are created only in the six run-alone Ui.Tests classes, which the `build-and-test` skill and this guide must list identically. They do not prove the prose is accurate, and the window check is pattern-based (`new Window`/`new MainWindow`, `.Show()`/`.ShowDialog()`). `tools/visual-fixtures` refuses a run of more than 48 captures in one process and stops above a 3,072 MB working set (both overridable per run; [README](../../tools/visual-fixtures/README.md)). Domain.Tests and Application.Tests additionally check assembly references. Use `tools/perf-benchmarks` and visual fixtures. Phase 34B/C resolved preview delay, price history repeated scans, redundant official requests, bitmap allocations and font/package overhead; do not reopen those without evidence. Remaining concerns include large Associate workspace, test hangs/font-stack exhaustion, Windows resource/printing measurements, UI-thread SQLite contention and sync-folder lock behavior. These are candidates or hypotheses, not confirmed current defects.

Windows verification harnesses outside the solution: `tools/updater-offline-stager` (Phase 27) and, pre-RC.15, `tools/pricing-retention-harness` — a disposable console tool for the `CarowindsTest` account that drives the production dated-pricing sources, registration and SQLite repository with embedded synthetic fixtures and its own clock (no network, no system-clock change) for one past date; packaged separately by its `build-harness.sh`, never with the app. See [the fix record §11](../pre-rc15-post-closing-pricing-retention.md).
